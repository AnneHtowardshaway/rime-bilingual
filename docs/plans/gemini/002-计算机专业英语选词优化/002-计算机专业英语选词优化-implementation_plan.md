## 1. 问题理解

用户希望继续完善 Rime 选词，并进一步明确重点为计算机专业英语单词。

当前万象精确匹配词表由 scripts/build-programming-vocabulary.py 生成。源包括 tech_english_table 及其六种语言词库，再补 AI、Agent、日常和设备词库；英文精确命中后由 internet_english_filter.lua 插入第二候选。专用 ; / vv 入口使用 bilingual_english 聚合词库。

已核实的不足：algorithm、data structure、binary search、recursion、polymorphism、concurrency、parallelism、authentication、authorization、latency 等对应英文完整编码尚未收录到本地精确词表。这不等于上游英文补全完全不能输出它们，需在隔离引擎中区分本项目精确第二候选与上游偶然补全。

旧 tech_english.dict.yaml 和 tech_english_programming.dict.yaml 有中文拼音到英文的条目，已经接入 bilingual_english 的 ; / vv 专用入口，但未接入普通模式精确 TSV。此前静态排查将“未入精确 TSV”误写为“未入聚合”，实施前已通过实际聚合文件更正。旧表还存在可疑或歧义编码，例如 REST 的 reset、closure 的 bibaot；不能为增加覆盖而直接全量接入。

另有编码语义冲突：hashmap 已输出 Rust 的 HashMap，linkedlist 已输出 LinkedList；增加通用 hash map / linked list 时必须保留这些规范 API 输出。

目标：补齐计算机基础专业英语，并提供英文全拼与经过核对的中文拼音选词；保留已有编码与混输行为。

## 2. 范围与不做范围

交付范围：

1. 新增至少 300 个经过核对的计算机术语，覆盖算法/数据结构、面向对象/类型、操作系统/并发、网络/安全、数据库/分布式和性能/工程实践。
2. 每个术语提供不带空格标点的英文全拼编码，例如 datastructure → data structure；为至少 50 个高频概念提供中文拼音编码，例如 suanfa → algorithm、shujujiegou → data structure。遇到现有码冲突保留原输出，使用有意义的消歧编码。
3. 既有同义或 API 编码不抢占，通用类型名用明确前缀或扩展编码，例如 cshashmap → hash map；最终命名按冲突检查确定。
4. 新词同时挂载普通中文模式精确选词与 ; / vv 技术英文入口；验证技术入口前缀补全、中文前段已选择后的接续和数字键上屏。
5. 为至少 30 个新增高频概念补充中文候选的准确专业英文释义，让中文伴学显示与英文选词覆盖相互配合。
6. 更新使用示例、维护规则、计划与真实复盘，保留代码未暂存。

不做范围：通用中文首选重调、上下文调频改造、默认开启模糊音、模型或上游版本升级、英文词频学习重写、改变英文第二候选约定、界面改版、离线安装包重建/草稿附件更新、读写实际私人词库或正式部署、暂存/提交/推送。

## 3. 风险等级与 Profile 依据

采用标准任务 Profile，风险中等：主要为公开词库和生成链变更，但中文拼音编码会与中文候选和已有英文码重合，需要保护现有输出与完整上屏。

仓库无 docs/ai-coding-standards/ 和 docs/requirements/，执行用户给出的十项计划及双写规则；不额外建立不存在的业务需求资产库。

已有安装包相关修改：README.md、docs/macos.md、docs/windows.md、scripts/test.sh 及 packaging/、打包脚本/测试、third_party/nsis/、001 文档均保留。本轮修改共享文件时仅作必要增量，不撤销原改动。

4. 对全部新增编码与两张现有精确词表做交叉冲突分析，记录保留旧码、复用同词和新设消歧码的结果。

## 6. 核心设计方案

沿用现有 Rime 字典格式、table_translator、聚合词库与精确插入过滤器；不新增依赖或新的运行时排序机制。

词库按业务主题用中文注释组织，术语名保留惯用大小写。通用概念和语言 API 分开编码，不能把 hashmap 的 HashMap 改成 hash map；普通多词术语的英文编码连写，候选上屏保留原空格、连字符和符号。

新增词库采用低于现有 API 主词的权重，结合生成器冲突测试和变更前后映射比较，确保原 4240 个编码的目标文本不变。若同一码已对应相同术语，则复用，不靠重复行虚增新增数；以新增且去重的独立术语计数，英文编码、中文拼音及缩写别名均不重复计数；术语数与编码数分别统计。

为同一个术语提供英文全拼和明确中文拼音两种入口。中文拼音命中时保留原中文首选，并将英文按当前规则插入第二项；未输入完整编码不提前插入，自然中文选词仍可用。类似 jicheng 等歧义词只使用明确语义编码，例如 leijicheng，最终按碰撞检查和真实引擎验证确定。

专业释义走现有 technical-glossary-en.tsv 优先表。仅输出已有术语的正确英语释义，不新增在线翻译、不自动替换中文、不引入全词表热路径扫描。

## 8. 枚举、错误码与文档影响

无业务枚举、错误码或公开 API 变更。新增词库属于已有词库聚合契约，不扩展字段。生成器和验证失败沿用非零退出码与具体文件/编码诊断。

教程需区分英文全拼、中文拼音、语言 API 消歧码、; / vv 补全和完整编码精确第二候选；示例须来自实际引擎结果。引用权威资料仅记录名称来源与链接，不复制长段正文。
